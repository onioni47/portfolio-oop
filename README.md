# portfolio-oop
객체지향프로그래밍 포트폴리오 개선과제 

# 1. Project Overview

기존 포트폴리오 페이지를 개선하여 프로젝트를 직접 추가하고, 설명하고, 삭제할 수 있는 포트폴리오 웹페이지를 제작했습니다.
기존에는 프로젝트 외의 자신을 표현하는 간단한 정보들을 화면에 표시하는데 중점을 두었다면 개선 후에는 객체 지향 프로그래밍을 적용하여 프로젝트에 중점을 두어 프로젝트 데이터 관리와 화면 표시 기능을 분리했습니다. 

## 주요기능 
- 프로젝트 추가
- 프로젝트 목록 조회
- 프로젝트 삭제
- 필수 입력값 검증
- LocalStrogae를 이용한 데이터 저장 및 유지

# 3. 객체지향 설계 

## 3-1 주요 객체와 책임

## (1) Project

하나의 프로젝트를 담당합니다.

- 프로젝트 제목, 설명, 기술 정보 저장
- 필수 입력값 검증
- 빈 문자열이 포함된 프로젝트 생성 방지 

## (2) ProjectManager

프로젝트 목록과 데이터를 관리합니다.

- 프로젝트 추가 및 삭제
- 프로젝트 목록 반환
- LocalsStroage를 활용한 저장 및 불러오기
- Project 객체인지 확인한 후 목록에 추가 ( ProjectManager는 Project 객체만 추가하도록 검사하여 프로젝트 목록에 잘못된 데이터가 들어가는 것을 방지 ) 

## (3) ProjectRender

프로젝트를 웹페이지에 표시합니다.

- 프로젝트 목록을 카드 형태로 출력
-  프로젝트별 삭제 버튼 생성
-  삭제 버튼을 누르면 ProjectManager에 삭제 요청
 
## 3-2 객체 간 협력

사용자가 입력 폼에 프로젝트 정보를 입력하면  Project 객체가 생성됩니다. 생성된 객체는 ProjectMangaer에 전달되어 목록에 저장됩니다. 이후 ProjectRenderer가 프로젝트 목록을 가져와 화면에 표시합니다. 또 삭제 버튼을 누르면 ProjectRenderer가 ProjectManager의 삭제 기능을 호출하고, 삭제된 목록을 다시 화면에 나타냅니다. 

## 3-3 적용한 객체지향 개념

- 클래스와 객체: Project, ProjectMangaer, ProjectRenderer 클래스를 정의하고 객체를 생성하였습니다.
- 책임 분리: 데이터 검증, 프로젝트 관리, 화면 표시 기능, 삭제 기능 등 각각 다른 클래스로 분리하여 수행하도록 하였습니다.
- 객체 참조: 객체를 변수에 저장하면 변수는 객체 자체가 아니라 객체가 저장된 위치를 참조합니다.

 const project = new Project(
    "My Portfolio",
    "Personal portfolio website",
    "HTML, CSS, JavaScript"
);

manager.addProject(project);

여기서 project변수는 생성된 Project 객체를 참조합니다. 이 변수를 addProject()에 전달하면 해당 객체를 가리키는 참조값이 전달되어 ProjectManager의 목록에 저장됩니다. 
- 객체 간 협력: ProjectRenderer가 ProjectManager의 메서드를 호출하여 프로젝트 삭제를 처리합니다.
- 캡슐화: 관련된 데이터와 기능을 하나의 클래스로 묶어 관리하는 개념으로 Project 클래스는 프로젝트의 제목, 설명, 기술 정보와 입력값 검증 기능을 모두 모아 함께 관리합니다.

# 4. 주요 설계 결정

(1) 클래스별 책임 분리

모든 기능을 하나의 코드에 작성하는 대신 세 개의 클래스로 분리했습니다. 이를 통해 기능별 수정이 쉬워지고 코드의 역할을 파악하기 쉬워졌습니다. 

(2) 프로젝트 데이터 검증 및 저장

Project 생성 시 제목, 설명 기술 정보가 비어 있는지 검사하도록 했습니다. 또한, ProjectManager에서 Project 객체만 추가할 수 있도록 검사하고, LocalStorage를 활용하여 새로고침 후에도 데이터가 유지되도록 했습니다. 

(3) 설계 규칙 

| 설계 규칙 | 설명 | 적용 코드 |
|---|---|---|
| 필수 입력값 검증 | 제목, 설명, 기술 정보는 반드시 입력해야 한다. | `Project`의 `trim()` |
| 객체 유형 검증 | Project 객체만 프로젝트 목록에 추가할 수 있다. | `instanceof Project` |
| 데이터 저장 | 프로젝트 추가 및 삭제 후 데이터를 저장한다. | `saveProjects()` |
| 데이터 불러오기 | 저장된 프로젝트 데이터를 다시 불러온다. | `loadProjects()` |
| 목록 조회 및 표시 | 프로젝트 목록을 가져와 화면에 표시한다. | `getProjects()`, `render()` |

# 6. 다른방법과의 이점과 한계

## 장점

- 클래스별 책임이 분리되어 코드 이해와 수정이 쉬워졌습니다.
- Project 객체를 통해 프로젝트 데이터의 구조를 일정하게 유지할 수 있습니다.
- LocalStorage를 이용하여 별도의 서버 없이 데이터를 저장할 수 있습니다.

## 한계

- LocalStorage를 사용하므로 다른 기기나 브라우저와 데이터가 자동으로 동기화되지 않습니다.
- 현재틑 프로젝트 수정 기능이 구현되어 있지 않습니다.
- 클래스별 기능이 분리되어 있지만, 프로젝트 규모가 커지면 추가적인 구조 개선이 필요하다는 한계가 있습니다.

# 7. 실행 방법

1. GitHub의 portfolio-oop 저장소에서 HTML, CSS, JavaScript 파일을 작성하고 수정합니다.

2. 변경한 파일을 GitHub 저장소에 Commit하여 반영합니다.

3. 저장소의 Settings → Pages에서 배포 설정을 확인합니다.

4. GitHub Pages가 저장소의 코드를 바탕으로 웹페이지를 자동으로 배포합니다.

5. 배포가 완료되면 생성된 GitHub Pages URL에 접속하여 변경된 페이지를 확인합니다.

6. 프로젝트 입력란에 제목, 설명, 기술 정보를 입력하고 Add Project 버튼을 눌러 프로젝트를 추가합니다.

7. 각 프로젝트의 Delete 버튼으로 프로젝트를 삭제할 수 있습니다.

8. 페이지를 새로고침하여 LocalStorage에 저장된 프로젝트 데이터가 유지되는지 확인합니다.
